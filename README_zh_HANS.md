Capsule 让导出变得快速而顺畅，只需一次点击，就能把成百上千个资产导出为多种格式。

本仓库是 [Takanu/Capsule](https://github.com/Takanu/Capsule) 的社区分支，由 [Kokkorylien](https://github.com/Kokkorylien) 维护。它不是 Takanu 的官方发行版。

> **Blender 兼容性**
>
> 本版本理论上支持 **Blender 4.0.2**，并且**没有在其他任何 Blender 版本上测试过**。其他版本理论上可能可以使用，但不受支持；请先备份场景，并自行承担风险。

> **性能**
>
> 在启用了大量**精简（Decimate）**和**数据传递（Data Transfer）**修改器的场景中，本分支的导出速度**远快于它 fork 来源的上游版本**。详见[为什么有这个分支](#为什么有这个分支)。

## 为什么有这个分支？

与上游项目相比，本分支最主要的区别是：当场景中包含大量**精简（Decimate）**和**数据传递（Data Transfer）**修改器时，导出性能会明显不同。

上游插件在逐个导出目标时，会让整个场景中的这些修改器一直保持启用。于是每次导出时，Blender 都可能对并不属于当前导出目标的对象求值大量修改器，造成不必要的开销。

本分支加入了**智能修改器导出（Smart Modifier Export）**：

- 导出开始前，记录场景中每个精简/数据传递修改器原本的视口和渲染可见性。
- 暂时关闭整个场景中的这些修改器，因此构建导出列表和写入第一个目标时，不会对全场景进行求值。
- 只重新启用当前正在写入的目标所属的修改器，包括数据传递修改器所引用的源对象上的修改器。
- 导出结束后，把所有修改器恢复到原本的可见性。

因此，在启用了大量精简/数据传递修改器的场景中，本分支的导出速度会比上游版本**快很多**。具体提升幅度取决于场景、修改器数量以及 Blender 的依赖图，并不是一个固定倍数。导出结果不会改变：导出前就处于禁用状态的修改器会保持禁用，导出结束后场景也会恢复原状。

## 功能

* **智能修改器导出（主要性能改进）** - 只让当前正在写入的导出目标保留精简和数据传递修改器处于启用状态，其他集合的修改器在导出期间暂时关闭。这样既能保持大场景的导出速度，又不会改变导出结果。

* **批量导出** - 一次点击即可为成百上千个对象和集合设置导出选项，再一次点击完成导出。

* **导出列表** - 浏览并搜索所有标记为导出的对象和集合，快速调整它们的设置。

* **原点导出** - 决定导出文件中的原点位置，无需在导出前手动移动对象。

* **导出预设** - 为不同的导出格式创建详细、可复用的导出预设，支持 Alembic、Collada、FBX、GLTF、OBJ、STL 和 USD/USDZ。

* **自动文件夹结构** - 按指定规则自动生成文件夹，帮助整理复杂的导出结构。

* **简体中文界面** - 自带独立翻译层和完整的简体中文翻译。

## 安装

- 从本分支的 [Releases 页面](https://github.com/Kokkorylien/Blender-GLBExporter-Capsule/releases)下载发行版。
- 确保 ZIP 文件名为 `Capsule.zip`，并且压缩包根目录下包含 `Capsule/` 文件夹。
- 在 Blender 中打开 **编辑 > 偏好设置 > 插件 > 安装...**，选择 `Capsule.zip`，然后启用 **Capsule**。

## 常见问题

**这个插件支持哪个 Blender 版本？**

本版本理论上支持 **Blender 4.0.2**，没有在其他任何 Blender 版本（包括更旧或更新的版本）上测试过。其他版本理论上可能可用，但不受支持；请先备份场景。

**为什么导出比上游版本快？**

因为导出时不会让整个场景中的精简和数据传递修改器一直保持启用。完整说明见[为什么有这个分支](#为什么有这个分支)。

**智能修改器导出会改变场景或导出结果吗？**

不会。它会记录原本的可见性，临时关闭高开销修改器，只启用当前目标需要的修改器，并在导出结束后恢复原状。导出前就被有意禁用的修改器会保持禁用。

**这个插件怎么用？**

可以先参考上游的 GitHub Wiki：https://github.com/Takanu/Capsule/wiki

**这个分支的 bug 应该在哪里反馈？**

请在本仓库提交 issue：https://github.com/Kokkorylien/Blender-GLBExporter-Capsule/issues

**Capsule 目前有哪些不能导出的情况？**

有几种场景可能无法顺利导出：

* 没有通过对象原点绑定到骨架骨骼上的动画 - 这类动画很可能会导出失败，建议改用场景原点。

* 骨骼约束 - 导出预设的 Armature 标签页中有“Preserve Armature Constraints”按钮，可以在导出带骨骼约束的骨架时尝试使用。不过该功能目前仍是实验性的，结果可能不稳定。

## 把导出预设保存为文件

已存储的导出预设（插件偏好设置 > Capsule > Stored Export Presets）原本保存在 Blender 的 `userpref.blend` 中，不方便查看、备份或在其他机器之间共享。现在偏好设置面板会显示该路径，并新增：

* **Export（导出）** - 把所有已存储预设（或只导出选中的预设）写入可读的 `capsule_export_presets.json` 文件。
* **Import（导入）** - 从该文件读回预设。导入后按 F9 可以设置 `Import Mode`，选择追加到现有列表或替换现有列表。
* **Show Settings Preview（显示设置预览）** - 以只读方式汇总选中预设，只列出它实际修改的选项，因此无需启用预设也能理解 `NekoMdl_Shape` 这类预设的作用。列表旁的信息按钮会以弹窗显示同样的摘要，控制台按钮则会打印所有选项。

预设文件带有版本号（`"schema": 1`），以英文界面文本为键，并以 UTF-8 JSON 写入，因此可以 diff，也可以放进版本库管理。无法识别或不支持的条目会被跳过，而不会导致整个导入失败。

## 语言支持

Capsule 不再依赖 Blender 内置的字典式界面翻译。那种方式会把简短的英文单词（包括插件名）机械地翻译掉，并留下半中半英的界面。现在插件自带翻译文件：

* `translations/zh_HANS.json` - 简体中文。
* 没有对应文件的语言，或文件中没有对应条目的字符串，会回退到英文，并明确排除在 Blender 内置翻译之外。

语言会根据 Blender 自身的语言自动选择，也可以在插件偏好设置中强制指定（Extra Settings > Language）。由于属性标签是在 Blender 中注册的，切换语言后需要重新加载插件 - 使用 **Reload Add-On** 按钮即可。

要添加其他语言，可以把 `zh_HANS.json` 复制为 `<语言代码>.json`，翻译其中的值（键保持英文），然后重新加载插件。尚未提供翻译的文件格式选项列表会有意保持英文，而不是进行机械翻译。
